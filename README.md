# SN76489 VGM Player for Raspberry Pi Pico

Raspberry Pi Pico（MicroPython）から **SN76489AN** を直接制御して、microSD に入れた **VGM ファイル**を再生するプレイヤーです。SN76489AN は 1 個でも 2 個でも使えます。

VGM には他の音源 IC（YM2612 など）のデータも入っていますが、このプレイヤーは **SN76489 のデータだけ**を取り出して鳴らし、それ以外は読み飛ばします。

## 特徴

- microSD の `/sd/vgm` 以下にある VGM を、**ファイル名順に連続再生**（サブフォルダも対象。拡張子がなくても、**ファイルの中身で VGM かどうかを判定**）
- `/WE` と `READY` を監視して、SN76489AN に**適切なタイミングで書き込み**
- **SN76489 を 2 個**使う構成に対応（VGM のデュアルチップ、疑似ステレオなど）
  - テスト用に「1 個目だけ」「2 個目だけ」「両方」を選択可能。1 個だけの回路で、VGM の 1 個目と 2 個目のどちらの出力を鳴らすかも切り替え可能
- **クロックを Pico の PWM で生成**（VGM のヘッダに書かれたクロックに、曲ごとに追従）。外部水晶も使用可能
- クロックの違いによる**音程のずれを自動補正**
- **音程シフト**（半音単位、小数可。曲ごとの指定も可能）
- **音量調整**（減衰量の追加）と**チャンネルごとのミュート**
- 電源 ON 直後の不定状態を**消音**し、少し間を置いてから再生開始
- `main.py` として保存すれば、電源 ON で自動再生

## 必要なもの

- Raspberry Pi Pico（MicroPython を書き込み済み）
- SN76489AN × 1〜2（5V 動作）
- microSD スロット（SPI 接続）と microSD カード
- `sdcard.py`（MicroPython 用の SD カードドライバ）
- クロックを外部水晶で供給する場合: 3.579545MHz などの水晶発振器

## 配線

Pico の GPIO 番号は、`main.py` の冒頭の設定で変更できます。初期値は次のとおりです。

| 信号 | GPIO |
|---|---|
| データバス（2 個で共通） | GP0〜GP7 |
| SN76489 ① `/WE` | GP10 |
| SN76489 ① `READY` | GP11 |
| SN76489 ① `/CE` | GP12 |
| SN76489 ② `/WE` | GP13 |
| SN76489 ② `READY` | GP14 |
| SN76489 ② `/CE` | GP15 |
| microSD `MISO`（SPI0） | GP16 |
| microSD `CS` | GP17 |
| microSD `SCK` | GP18 |
| microSD `MOSI` | GP19 |
| クロック出力（PWM） | GP22 |

- **データバス**: GP0 に送信バイトの bit7、GP7 に bit0 を出力します（SN76489 の `D0` が MSB）。IC のデータ端子との対応は、データシートで確認してください。
- **`/CE`**: GND に直結して常に Low にしても動作します。その場合、`/CE` 用の GPIO（GP12、GP15）は未接続にしてください（GND につないだ線に、GPIO を一緒に接続しないこと）。
- **クロック**: GP22 を SN76489 の CLOCK 入力に接続します。2 個使う場合は、両方の CLOCK 入力に分岐します。外部水晶を使うときは、`CLOCK_MODE = "external"` にして、GP22 は使いません。

### ハードウェアの注意

- SN76489AN は **5V 動作**、Pico の GPIO は **3.3V** です。`READY` は SN76489AN の出力なので、Pico に入れる前に、**分圧やレベル変換**で 3.3V 以下にしてください。
- Pico が起動する前は `/WE` が不定になり、誤書き込みの原因になります。`/WE` を 10kΩ 程度で電源（5V 側）にプルアップしておくと安全です。
- CLOCK 入力の H レベルのしきい値と、動作クロックの範囲は、データシートで確認してください。
- **microSD 側にプルアップ抵抗を付けると、読み書きできなくなることがありました**（作者の環境）。うまく動かないときは、プルアップを外してみてください。
- 作者の環境では、SN76489 の電源に **RC フィルタ**（約 2.4Ω と 1000µF）を入れて、USB 充電器から給電すると、ノイズが小さくなりました。PC の USB から給電するとノイズが乗ることがあります。

## セットアップ

1. Pico に MicroPython を書き込みます。
2. `sdcard.py` を Pico の `/lib` に入れます。
   - Thonny: 「ツール」→「パッケージを管理」で `micropython-sdcard` を検索してインストール
   - mpremote: `mpremote mip install sdcard`
3. `main.py` を Pico に保存します。
4. microSD カードを **FAT32** でフォーマットし、`vgm` フォルダを作って、VGM ファイルを入れます（32GB を超えるカードは、出荷時に exFAT のことがあり、その場合は FAT32 にフォーマットし直してください）。
5. 電源を入れると、消音してから少し待ち、再生を始めます。

## 使い方

- 再生順は、**ファイル名順**です。順番を決めたいときは、`01_xxx.vgm`、`02_yyy.vgm` のように、先頭に番号を付けてください。
- サブフォルダは、名前順の位置で中身が展開されます。

  ```
  /sd/vgm/01_a.vgm
  /sd/vgm/02_album/01_x.vgm
  /sd/vgm/02_album/02_y.vgm
  /sd/vgm/03_b.vgm
  ```

  → `01_a` → `02_album/01_x` → `02_album/02_y` → `03_b` の順に再生します。
- `.vgz`（gzip 圧縮）は非対応です。パソコンで解凍して `.vgm` にしてください。
- **日本語などのファイル名**: パスをバイト列のまま扱うので、再生できます。ただし FAT の仕様で、表示されるファイル名は、短縮名のような読みにくい文字列になります。
- 実行中のログは、シリアルコンソール（Thonny のシェルなど）に表示されます。

## 設定

設定は、`main.py` の冒頭の定数を書き換えます。

### 再生

| 設定 | 初期値 | 説明 |
|---|---|---|
| `VGM_DIR` | `"/sd/vgm"` | VGM を置いたフォルダ |
| `RECURSIVE` | `True` | サブフォルダも対象にする |
| `MAX_DEPTH` | `4` | サブフォルダを何階層下まで探すか |
| `REPEAT_PLAYLIST` | `False` | 全曲の再生後に、最初から繰り返す |
| `LOOP_COUNT` | `1` | 1 曲ごとのループ回数（`0` でループなし、`-1` で無限） |
| `BUF_SIZE` | `2048` | ファイルの読み込みバッファ（バイト） |
| `STARTUP_DELAY_MS` | `1500` | 電源 ON 後、最初の曲が始まるまでの無音時間（ms） |

### microSD

| 設定 | 初期値 | 説明 |
|---|---|---|
| `SD_MOUNT` | `"/sd"` | マウント先 |
| `PIN_SD_CS` / `PIN_SD_SCK` / `PIN_SD_MOSI` / `PIN_SD_MISO` | `17` / `18` / `19` / `16` | SPI0 のピン |
| `SD_BAUDRATE` | `4000000` | SPI の速度。読み込みエラーが出るときは下げる（例: `1320000`） |

### クロック

| 設定 | 初期値 | 説明 |
|---|---|---|
| `CLOCK_MODE` | `"vgm"` | `"vgm"`: VGM のヘッダのクロックに合わせて、曲ごとに出力を切り替える / `"fixed"`: `CLOCK_OUT_HZ` で固定 / `"external"`: 外部水晶を使う（Pico からは出力しない） |
| `PIN_CLOCK` | `22` | クロックを出力する GPIO |
| `CLOCK_OUT_HZ` | `2000000` | `"fixed"` のときの周波数（`"vgm"` でも、起動時に使う） |
| `CLOCK_MIN_HZ` / `CLOCK_MAX_HZ` | `1000000` / `4000000` | `"vgm"` のとき、この範囲に収めて出力する（データシートで動作範囲を確認して調整） |
| `CLOCK_EXT_HZ` | `3579545` | `"external"` のときの、外部水晶の周波数 |
| `CLOCK_TOLERANCE` | `0.003` | クロック比がこの範囲内なら、音程補正を省略する（0.3%） |

PWM は、システムクロックの整数分周でクロックを作るので、3.579545MHz ちょうどにはなりません。Pico は、実際に出力されている周波数を読み戻して、音程を補正します。`machine.freq(250_000_000)` を設定しているのは、分周の刻みを細かくして、誤差を小さくするためです。

### 音程・音量・ミュート

| 設定 | 初期値 | 説明 |
|---|---|---|
| `PITCH_SHIFT` | `0.0` | 音程を半音単位で上下（`+2.5` で半音 2.5 個ぶん高く、負の値で低く） |
| `PITCH_BY_FILE` | `{}` | 曲ごとのシフト量。キーは、ファイル名またはフルパス（例: `{"01_xxx.vgm": 2.5}`） |
| `MASTER_ATTEN` | `0` | 全体の音量を下げる段数（1 段が約 2dB、`15` で無音） |
| `CHANNEL_ATTEN` | すべて `0` | チャンネルごとに追加で下げる段数。VGM の 1 個目と 2 個目それぞれに `[トーン1, トーン2, トーン3, ノイズ]` で指定 |
| `MUTE_CH` | すべて空 | ミュートするチャンネル。`1`〜`3` がトーン、`4` がノイズ（例: `[[4], []]` で VGM の 1 個目のノイズを消音） |

- 音量調整は**下げる方向のみ**です（SN76489 の音量は、減衰量で指定する仕様のため）。上げたいときは、アンプなどのハードウェア側で行ってください。
- 音程シフトは、音程レジスタの値を計算し直して実現しています。高い音ほど、整数への丸め誤差が大きくなります。

### テスト用の出力設定

| 設定 | 初期値 | 説明 |
|---|---|---|
| `PLAY_MODE` | `"both"` | 使う物理 IC。`"both"`: 2 個とも / `"first"`: 1 個目だけ / `"second"`: 2 個目だけ |
| `SINGLE_SOURCE` | `0` | `"first"` / `"second"` のとき、VGM の何個目のチップのデータを鳴らすか（`0`: 1 個目、`1`: 2 個目） |
| `SWAP_CHIPS` | `False` | `"both"` のとき、VGM の 1 個目と 2 個目を、物理 IC 側で入れ替える |

使わない物理 IC には、書き込みも `READY` の待ちも行いません。2 個目を未接続の回路でも、`PLAY_MODE = "first"` にすれば動きます。

## 仕組み

- **書き込み**: データバスに値を出して `/WE` を Low にし、`READY` が Low → High に戻る（約 32 クロック後）のを待ってから、`/WE` を High に戻します。待ちにはタイムアウトを設けています。
- **時間管理**: VGM の待ち時間は 44100Hz のサンプル数で表されます。曲の開始からの絶対時刻でタイミングを管理して、誤差が蓄積しないようにしています。
- **音程の補正**: 音程のレジスタ値 N を、`N' = N × (実機のクロック ÷ ファイルのクロック) ÷ 2^(シフト量/12)` に変換して書き込みます。
- **処理の流れ**: VGM のデータ → 音量調整・ミュート → 音程補正 → 物理 IC への書き込み

## 対応状況と制限

- SN76489 のコマンド（`0x50`: 1 個目、`0x30`: 2 個目）だけを再生します。YM2612 や YM2413 など、他の音源 IC のコマンドは読み飛ばします（待ち時間のコマンドは、すべて守ります）。
- Game Gear のステレオ設定（`0x4F`）や、PCM のデータブロックは無視します。
- ノイズの固定周波数（クロックの分周で決まる 3 種類）は、音程シフトとクロック補正の対象外です。ノイズが「チャンネル 2 の音程に連動」するモードのときだけ、連動してシフトします。
- 2 個のチップを持つ VGM を、1 個の IC で鳴らす場合は、どちらか片方のデータだけを再生します。
- microSD の読み込み中（バッファの補充のとき）は、再生が一瞬止まります。`SD_BAUDRATE` を上げる（安定する範囲で）と、影響が小さくなります。
- 書き込みの多い曲では、処理が間に合わないことがあります。`machine.freq()` の設定を、確認してください。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| `no SD card` と表示される | 配線（特に MISO・MOSI・SCK・CS）、`sdcard.py` が `/lib` にあるか、カードを FAT32 でフォーマットしているか。microSD 側のプルアップは外す。`SD_BAUDRATE` を下げる |
| `OSError: [Errno 2] ENOENT` | `VGM_DIR` のフォルダがない。microSD を `/sd` にマウントできているか、`vgm` フォルダがあるか |
| 音が出ない | クロックが出ているか（`CLOCK_MODE`、GP22 の配線）、電源（5V）、`/WE`・`READY` の配線。`READY` が変化しないと、書き込みはタイムアウト（1ms）で進みます |
| 音程がずれている | クロックの値と、VGM のヘッダのクロックを確認。ログに「クロック補正あり」と表示されます |
| 日本語のファイル名で `UnicodeError` | 最新の `main.py`（バイト列のパスで扱う版）を使う |
| 再生が遅れる・途切れる | `BUF_SIZE`、`SD_BAUDRATE` を調整。`machine.freq()` を上げる |
